# 발표 대본 — 돌담 오늘 (3분 + 질의응답)

- 발표 시간: **3분**, 본 발표 슬라이드 **1~6번**. 7번부터는 부록(질문이 나올 때만 보여 주기)
- 말하는 속도: 1분에 약 300자 → 본 발표 약 900자
- `[ ]`는 행동 지시, `(시간)`은 누적 시간 목표
- 슬라이드 노트에도 같은 요지가 들어 있어요 (PowerPoint 발표자 보기)

## 발표 전 체크리스트 (5분 전)
1. 배포 주소를 열어 홈이 뜨는지 확인 → https://doldam-today-jeju-project.vercel.app
2. **돌담지기에 질문 1번 해 보기**: 답이 나오고 호출 내역이 보이는지 (키 문제 있으면 아래 '시연 대안' 사용)
3. 바람과 돌담(3D)을 미리 한 번 열어 두기 (처음 열 때 몇 초 걸림)
4. 닉네임을 정하고 도장 2~3개 찍어 두기 → 내 수첩에서 돌벽이 채워진 상태로 시작
5. 화면 확대 100%, 알림·메신저 끄기, 발표 자료는 6번까지만 보이게 슬라이드 쇼 시작

## 1. 표지 (0:00 ~ 0:15)
안녕하세요. 제주 돌담 열네 곳을 다녀올 때마다 내 수첩의 돌벽이 채워지는 웹앱, **돌담 오늘**을 만든 ○○○입니다. [QR 가리키며] 오른쪽 QR로 지금 바로 열어 보실 수 있어요.

## 2. 기획 의도 (0:15 ~ 0:45)
제주 돌담은 바람 많은 섬이 쌓아 온 문화유산인데, 여행자에게는 그냥 지나치는 풍경이에요. 밭담, 환해장성, 방사탑이 어디에 있고 무엇이 다른지 한곳에서 알기도 어렵습니다.
그래서 돌담 열네 곳을 종류별로 알려 주고, 다녀올 때마다 수첩의 돌벽을 한 칸씩 채우게 만들었어요. 휠체어나 유아차로 다니는 분을 위한 무장애 정보도 담았습니다. 한 줄로 말하면 **"걷는 만큼 쌓이는 나만의 제주 돌담"** 입니다.

## 3. 내 돌담 수첩 (0:45 ~ 1:15)
핵심 기능입니다. [슬라이드를 보며] 명소에서 도장을 찍으면 돌벽의 빈 구멍이 돌로 채워지고, 열네 곳을 다 채우면 "돌담 장인"이 돼요. 돌은 모양이 제각각인 98개이고, 명소 하나가 일곱 개를 맡아요.
도장은 Supabase에 저장돼서 새로고침해도 남고, 완성한 돌벽은 닉네임과 함께 이미지로 저장해 공유할 수 있습니다.

## 4. 바람과 돌담 3D (1:15 ~ 1:45)
돌담이 왜 필요한지는 3D로 보여 드립니다. [3D 슬라이드] 기상청 오늘 풍속을 돌담 모형에 불어 넣으면, 담을 지난 바람은 주황색으로 약해지고 담 뒤 작물도 덜 흔들려요. 돌담을 치우면 차이가 바로 보입니다.
다만 줄어드는 비율은 원리를 보여 주는 **설명용 모형**이라서, 화면에도 실측값이 아니라고 밝혀 두었습니다.

## 5. 공공데이터와 AI 돌담지기 (1:45 ~ 2:40)
데이터는 기상청, 에어코리아, 한국관광공사, 제주도청, 무장애여행정보 등을 실제로 호출하고, 키는 서버에만 둡니다.
[시연 시작: 앱 화면으로 전환, 돌담지기 버튼] 돌담지기에게 물어볼게요. **"오늘 바람 센데 갈 만한 돌담 어디야?"** [답을 기다리며] Claude가 도구를 스스로 골라 날씨를 조회하고, 명소를 검색하고, 필요하면 상세까지 차례로 부릅니다. [답이 나오면 손으로 가리키며] 답변 위에 어떤 도구를 몇 건 불렀는지 그대로 보이고, 근거가 없는 내용은 지어내지 않도록 지시해 두었습니다.
(시연 20~30초. 끝나면 슬라이드 쇼로 복귀)

## 6. 정리와 다음 계획 (2:40 ~ 3:00)
정리하면 돌담 도감, 실제 지도, 3D 바람, 돌벽 수첩, AI 돌담지기를 만들었고 키는 서버에만 두었습니다. 다음에는 제주어와 설화 데이터를 붙이고, 근사 위치 세 곳을 현장에서 보정하겠습니다. 감사합니다.

## 예상 질문과 답 (부록 슬라이드 번호)

**Q1. API 키가 노출되지 않나요?** (부록 8번)
키는 Vercel 서버 환경변수에만 있고, 브라우저 코드에는 Supabase 공개(anon) 키만 들어갑니다. 빌드 결과물과 GitHub 기록 전체에서 키 문자열이 없는 것을 확인했고, `.env.local`은 저장소에 올라가지 않습니다.

**Q2. 바람이 줄어드는 수치는 실측인가요?** (4번)
아닙니다. 원리를 보여 주는 설명용 모형이고 화면에도 그렇게 적었습니다. 풍속은 기상청 실제 예보이고, 담 뒤 감소 비율만 모형입니다.

**Q3. 돌담지기가 거짓말하면 어떡하나요?** (부록 11번)
세 겹으로 막았습니다. ① 시스템 지시에서 도구 결과에 없는 사실을 말하지 않게 했고, ② 도구 호출 내역이 화면에 보여서 근거를 확인할 수 있으며, ③ 미세먼지가 추정값이면 "추정"이라고 밝히게 했습니다.

**Q4. 에이전트가 실제로 도구를 여러 번 부르는지 확인했나요?** (부록 11번)
가짜 Claude 서버를 세워서 처음부터 끝까지 돌려 봤습니다. 한 번에 도구 3개, 다음 차례에 4개를 부르고, 없는 명소 id는 오류로 안전하게 처리하는 것까지 확인했습니다. 여섯 개 도구는 모두 실제 공공 API 데이터로 응답했습니다. 실제 Claude 응답은 [키 상태에 따라: 화면에서 보신 대로입니다 / 키 교체 후 확인합니다].

**Q5. Supabase 보안은요?** (부록 13번)
실습용 정책이라 누구나 읽고 쓸 수 있습니다. 실서비스라면 Supabase Auth로 로그인하고 본인 행만 다루게 바꿔야 합니다. 다음 계획에 넣었습니다.

**Q6. 위치가 정확한가요?** (부록 13번)
좌표 출처를 배지로 구분했습니다. 실측 경로 2곳, 한국관광공사 좌표 7곳, 위키백과 1곳, OpenStreetMap 1곳이고, 한담·김녕·우도 3곳은 점 하나로 정하기 어려워 "근사 위치"로 표시했습니다.

**Q7. 사진 저작권은요?**
한국관광공사 공공누리 1·3유형과 위키미디어 CC BY-SA 사진만 썼고, 모든 사진 아래에 출처와 라이선스를 적었습니다. 변경 금지(3유형) 사진은 크기만 줄이고 자르거나 합성하지 않았습니다.

**Q8. 왜 날씨 추천 앱으로 안 했나요?**
날씨 추천은 흔하고 오래 쓰이지 않을 것 같아서, 걷는 만큼 쌓이는 수집형 경험으로 바꿨습니다. 날씨는 바람과 돌담 화면과 돌담지기의 근거로 남겼습니다.

**Q9. 모바일에서도 되나요?** (부록 14번)
네. 작은 화면에서 이름표를 키우고, 돌담지기는 하단 시트로 열립니다. 3D 화면은 따로 불러와서 첫 화면을 절반으로 줄였습니다.

**Q10. 다음에 무엇을 더 하나요?** (부록 13번)
제주어(방언사전·속담)와 설화·신화를 연결하고, 버스 정보로 저상버스 찾아가기를 붙이고, 로그인과 대화 기록 저장을 추가하겠습니다.

**Q11. 무엇이 가장 어려웠나요?**
모양이 제각각인 돌을 틈 없이 맞물려 채우는 돌벽을 만든 것입니다. 보로노이 분할로 돌 98개를 늘 같은 모양으로 만들고, 명소 하나를 이웃한 돌 일곱 개로 묶었습니다.
